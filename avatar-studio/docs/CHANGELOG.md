
- Resend or renew a pending workspace invite (`f7d34b7`). Each row in the Workspace page's Pending invites list now has a button beside Revoke: Resend for an invite made with an email address, Renew for a link-only one. Either gives the same link a fresh 7-day expiry, so someone who has not got to it yet has another week. Resend also sends the email again when email sending is configured.
  - **Result:** the row says "Sent again" or "Renewed". The invite box shows the link with Copy link, and a line saying what happened: emailed again, the email failed (share the link instead), email sending is not configured, or the link was renewed. Each line ends with the new expiry date. A status line announces it to screen readers, and the focus stays on the button.
  - **API:** `POST /api/workspaces/:id/invites/:token` answers `{ invite, url, emailed, emailError? }`, as creating an invite does. It is for owners only. An expired, revoked, or unknown invite, or another workspace's, answers `404`; an invite that has already lapsed needs a new one. Each resend can send an email, so a second one within 5 minutes answers `429`.
  - **Code:** `renewInvite` in `src/lib/workspaces.ts`. Creating and resending share `deliverInvite` in `src/lib/invite-mail.ts`, which builds the link and sends the email.
  - An independent review found one blocking bug. A renew that read the invite just before it was accepted or revoked wrote it back for another week, so a used or revoked link could join again. The write now goes through only while the invite read is still stored (`putIf`), and a unit test removes the invite between the read and the write. From its optional findings: the 5-minute resend cooldown, the button keeping the focus, an always-present status line instead of announcing the whole link box, the row's own confirmation, and button labels that name the expiry.

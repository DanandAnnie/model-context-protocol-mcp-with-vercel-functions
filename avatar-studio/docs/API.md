# Avatar Studio API

Every screen in the app is backed by JSON routes under `/api`, and scripts can call the same routes.

## Authentication

Create a key in **Settings → Developer API** (the secret is shown once) and send it as a bearer token:

```
Authorization: Bearer as_live_…
```

- A key acts as the account, or the workspace, that was active when it was minted.
- Keys work in every access mode (open, shared password, Supabase accounts).
- Creating or revoking keys needs a signed-in browser session, never another key (`403` otherwise).
- Keys minted inside a workspace are revoked when that member leaves or is removed, and when the workspace is deleted.
- Unknown or revoked keys get `401`. Only tokens that start with `as_live_` are treated as keys; any other bearer value falls back to the normal session check.

Public routes need no key: `/api/videos/:id/captions`, `/api/videos/:id/cover`, `/api/videos/:id/view`, `/api/videos/:id/watch`, `/api/videos/:id/cta`, `/api/videos/:id/unlock`, `/api/videos/:id/lead`, `/api/talk/:id`, `/api/webhooks/:provider`, `/api/auth/*`, `/share/:id/preview.gif` (below), `/share/:id` (which takes `?autoplay=1` to start muted and `?loop=1` to repeat, the options the video page's Embed button offers, and `?embed=1`, the page an embed's iframe loads: the player alone, as large as the frame allows in the video's shape and centred in it, after any password or email form).

## Conventions

- Request and response bodies are JSON. Timestamps are ISO 8601 in UTC.
- Validation errors return `400` with `{ "error": "...", "issues": [...] }`. Missing or foreign items return `404`. Exceeding the monthly render allowance returns `429` with the usage and reset date. A render counts once it starts and keeps counting when the video is deleted, the trash is emptied, or the account's data is deleted (the month's count is kept in its own record); a render that fails to start, or that the provider later reports failed, is given back (once, to the month that counted it, which the video records as `countedIn`). A new workspace starts with its own allowance. Provider failures on submission return `502` with the provider's message.
- Ids are prefixed: `vid_`, `av_`, `tr_`, `key_`, `ws_`.

## Videos

### `POST /api/videos` — render a video

```json
{
  "title": "Open house walkthrough",
  "script": "Hi, I'm Dana. Welcome to 12 Maple Street…",
  "avatarId": "stock_1",
  "voiceId": "stock_voice_1",
  "aspect": "16:9",
  "background": { "type": "color", "value": "#f1f5f9" },
  "captions": true,
  "speed": 1
}
```

Instead of `script`, send `scenes` (1 to 20), each with its own `script` and `background`, and optionally its own `avatarId` and `voiceId` (the video's are used when omitted); the combined script must stay under 5000 characters. HeyGen renders the scenes as one v3 studio video (`POST /v3/videos`, `type: "studio"`, one scene each (`avatar_video` with the presenter, or a whole-frame `image` or `video` scene for one with `hidePresenter`)); D-ID refuses a scene that names another presenter or voice, and the demo renderer ignores the choice:

```json
{ "title": "Two scenes", "avatarId": "stock_1", "voiceId": "stock_voice_1",
  "scenes": [
    { "script": "First scene.", "background": { "type": "color", "value": "#0f172a" } },
    { "script": "Second scene.", "background": { "type": "image", "value": "https://example.com/bg.jpg" }, "avatarId": "stock_2", "voiceId": "stock_voice_2" }
  ] }
```

Returns `201` with `{ "video": Video }`. The video starts as `queued` or `processing`; poll `GET /api/videos/:id` or use a webhook.


### `GET /api/videos` — list the library

Query parameters, all optional: `q` (matches title, description, script, avatar, and voice), `status` (`processing`, which includes queued, `completed`, or `failed`), `folder` (a name; pass it empty for unfiled videos), `batch`, `sort` (`newest`, `oldest`, `title`, `views`), `limit` (1–200; omit it to receive every match), `review` (`pending`, `approved`, `changes`, or `none` for videos never sent for review), and `trash` (`true` or `1` lists the trash instead of the library, newest deletion first). Returns `{ "videos", "matched", "total", "hasMore", "folders", "rendering", "trashed" }`: `matched` counts the query's results before `limit`, `total` the whole library (never the trash), `folders` the names in use, `rendering` the renders still in flight, and `trashed` the videos in the trash. The newest ten in-flight renders are refreshed from the provider on the way out, so polling the list is enough to see completions.

### `GET /api/videos/analytics` — the library's share analytics as a CSV download

One row per video, newest first: `id`, `title`, `status`, `created`, `folder`, `duration_sec`, `views`, `views_7d` (views in the last seven UTC days including today), `last_viewed`, `watched_25` … `watched_100`, `finish_rate` (percent of views that played to the end; empty before any view), `cta_clicks`, and `share_link` (built from `APP_URL` when set). Cells are quoted and formula-safe, with a byte-order mark for Excel.

### `POST /api/cinematic` — a cinematic shot

`{ "prompt", "avatarIds", "aspect"?, "resolution"?, "duration"?, "enhancePrompt"?, "title"?, "folder"? }` starts a shot HeyGen directs from the description (its Cinematic Avatar: `POST /v3/videos` with `type: "cinematic_avatar"`, `prompt`, `avatar_id` as the presenters' looks, `aspect_ratio`, `resolution`, `duration` or `auto_duration`, `enhance_prompt`, and `title`) as a library video → `201 { "video" }` (`502` with the failed video when HeyGen refuses to start it, with its reason). `prompt` is 10 to 4,000 characters; `avatarIds` names one to three of the account's presenters, each once (another account's, or one the library does not list, is a `404`; a photo avatar is prepared at HeyGen first, as for any render); `aspect` is `"16:9"` (the default), `"9:16"`, or `"1:1"`; `resolution` `"1080p"` (the default) or `"720p"`; `duration` 4 to 15 seconds or `"auto"` (the default) for HeyGen to choose; `enhancePrompt` has HeyGen expand a short description first; `title` defaults to the description's first words. HeyGen refuses a `callback_url` for these, so the shot is followed by asking (`GET /v3/videos/:id`), like any render without a webhook. An `Idempotency-Key` header (8 to 100 letters, digits, `-`, `_`) fixes the new video's id, so a shot retried with the same key after a lost answer returns the video already started, with its row reserved and HeyGen given the video's id as its own key, as for template renders; the same key for another description, presenters, shape, quality, length, enrichment, title, or folder, or for a video since moved to the trash, is a `409`; only the request that starts the shot records it in the activity feed. The video carries `cinematic: { prompt, avatarIds, avatarNames, durationSec?, enhancePrompt? }`, an empty `script`, `captions: false`, and the presenters' names as `avatarName`; it counts against the month's allowance like any render. A retry sends the shot again, naming the presenters as they are then; the library search matches the description, and the share page has no transcript. "Make other sizes", subtitles, caption edits, and saving it as a template are refused (`400`), and the editor offers no copy, as there is no script. `/api/status` reports `cinematicShots`. Editors only. The demo renderer stands its sample video in, as long as asked (8 seconds when HeyGen would choose); D-ID has none (`400`). The HeyGen call follows its API reference and is checked only against stubbed requests.

### `GET /api/studio-templates`, `GET /api/studio-templates/:id`, `POST /api/studio-templates/:id/videos` — HeyGen Studio templates

Layouts made in HeyGen Studio and marked for the API, with named slots for text, media, a presenter, and a voice. `GET /api/studio-templates` → `{ "templates": [{ id, name, thumbnailUrl?, aspect? }], "available" }`, the renderer's API-ready templates (HeyGen `GET /v3/templates`, up to five pages of 100, reused for two minutes; the same for every account, as they live in the renderer's account; two stand-ins in demo mode). `GET /api/studio-templates/:id` → `{ "template": { id, name, aspect?, variables, scenes: [{ id, script, variables }] } }` (HeyGen `GET /v3/templates/:id`): `variables` keyed by name with the template's current values, kept to the fields this studio uses (`{ type: "text", content }`, empty when unfilled; `{ type: "image" | "video", asset?, fit?, play_style?, volume? }` and `{ type: "audio", asset? }`, with an asset given by link or asset id, another form left out; `{ type: "voice", voice_id, locale? }`; `{ type: "character", avatar_id }`, read from a former field name on older templates; a type this studio does not know is left out), `thumbnailUrl`?, and each scene's script with `{{name}}` left in; an unknown template is a `404`; a template's detail is reused for a minute. Viewers can read both. `/api/status` reports `studioTemplates`.

`POST /api/studio-templates/:id/videos` → `{ "title", "captions"?, "variables"? }` renders the template (HeyGen `POST /v3/templates/:id` with `variables`, `title`, `caption`, and the webhook's `callback_url` when one is set) as a library video → `201 { "video" }` (`502` with the failed video when HeyGen refuses to start it). An `Idempotency-Key` header (8 to 100 letters, digits, `-`, `_`) fixes the new video's id, so a render retried with the same key after a lost answer returns the video already made (the same answer, with no second render, count, or activity). The video's row is reserved before HeyGen is asked, so a retry arriving while the first is still being sent is a `409` ("still being sent; try again in a moment"), and HeyGen gets the video's id as its own `Idempotency-Key`, so a start whose function died after HeyGen accepted it is replayed there rather than rendered again when retried two minutes later. The same key for another template, title, or captions, or for a video since moved to the trash, is a `409`. The form sends one key per render, renewed when what would be rendered changes, when the render is refused, or when it fails (`502`); a lost answer, or a `409` for a render still being sent, keeps it. Error messages name a slot as the form labels it (`Fill in "Open time"`). Each variable given replaces the template's own (it must be one of the template's, of the same type: otherwise a `400`). Every text is sent, as HeyGen fills no text a request leaves out, so a text with no default must be given (`400` naming it); a text holds up to 10,000 characters. Any other variable is sent only when given, so one left out keeps whatever the template holds in HeyGen Studio. Media are given as a public `https` link (`asset: { type: "url", url }`, with `fit` optional; a private address is a `400`) and keep the template's fit and playback unless given; a presenter must be the template's own or one of the renderer's library presenters the account sees, and a voice the template's own or one of the account's voices (`400` otherwise). The video carries `studioTemplate: { id, name, variables }` (the values sent) and a `script` of the scenes' scripts filled in (for captions, search, and the page); its aspect is the template's; it counts against the month's allowance like any render and is followed the same way. A retry sends the template again with the same values; "Make other sizes" and saving it as a template are refused (`400`), and the editor offers no copy, as the template owns the layout. Editors only. The HeyGen calls follow its API reference and are checked only against stubbed requests.

### `GET /api/templates`, `POST /api/templates`, `GET /api/templates/:id`, `DELETE /api/templates/:id` — saved templates

A template is a starting point for the editor: scenes (with any per-scene presenter), avatar, voice, aspect, quality, captions, and speed, up to 50 per account. Create one from a video you own with `{ "fromVideoId", "title"?, "description"? }` (the title defaults to the video's), or spell it out with `{ "title", "scenes", "avatarId"?, "voiceId"?, "aspect"?, "resolution"?, "captions"?, "captionStyle"?, "speed"?, "pitch"?, "emotion"?, "expressiveness"?, "motionPrompt"?, "accent"?, "avatarEngine"?, "moreBlinking"?, "transparent"? }` (scenes may carry a `layout`, a `speed`, an `overlay`, and `hidePresenter` like a video's). `GET /api/templates` returns `{ "templates" }`, newest first; the editor opens one at `/create?template=<id>`.

### `GET /api/videos/:id` — fetch; refreshes the status from the provider while rendering. Answers `{ "video", "shareOrigin" }`: `shareOrigin` is the origin public links are built on (`APP_URL` when it is set, else the request's own), the same one the share email uses, so copied, embedded, and posted links match it
### `PATCH /api/videos/:id` — `{ "title"?: string, "description"?: string, "folder"?: string, "shareDownload"?: boolean, "shareGate"?: boolean, "shareDisabled"?: boolean, "shareExpiresAt"?: string | null, "cover"?: string | null, "sharePassword"?: string | null, "shareCta"?: { "label", "url" } | null }` (`description`, up to 500 characters, is shown under the share-page player and becomes the link preview's description in place of the script excerpt, an empty string removes it, and a retried render keeps it; empty `folder` means unfiled; `shareDownload` shows a download button on the public share page; `shareGate` makes the share page ask for the viewer's email (and optionally a name) before the player shows, a soft gate for collecting leads rather than a lock (use `sharePassword` to protect a video); `shareDisabled` takes the share link offline: the share page, its captions, and the view, watch, and click beacons answer `404` to the public while the owner keeps full access; `shareExpiresAt` (an ISO 8601 time with a UTC offset, e.g. `2030-06-01T10:00:00+02:00` or `...Z`, in the future, or `null` to clear) does the same automatically once that time passes, stored as a UTC instant; `cover` (a `data:image/...` URL, PNG/JPEG/WebP/GIF, 2 MB decoded, or `null` to remove) sets a custom poster kept in its own record and served by `GET /api/videos/:id/cover` (the video carries `cover: { updatedAt, mimeType, bytes }`; `updatedAt` versions the URL); `sharePassword` (4–64 characters, or `null` to remove) protects the share link: visitors must enter it before the page plays, captions and beacons need the resulting cookie, and the video carries `shareLocked: true` while the password itself is kept only as a salted hash in its own record; `shareCta` puts a call-to-action button under the share-page player, label up to 40 characters and an http(s) link, `null` removes it)
### `DELETE /api/videos/:id` — moves the video to the trash: it leaves the library, its share page, captions, cover, and beacons answer `404` to the public, and the owner can still read and restore it for 30 days, after which it is deleted for good (side records included) the next time the library is listed; `?permanent=true` deletes a trashed video for good straight away (`409` for a video that is not in the trash). The video carries `deletedAt` while trashed
### `POST /api/videos/:id/restore` — brings a trashed video back to the library → `{ video }`; a live video is returned as is
### `POST /api/videos/folders` — `{ "from": "Q4", "to": "Q4 2026" }` renames a folder by moving every video in it (trashed ones included); an empty `to` removes the folder and leaves its videos unfiled; renaming onto an existing folder merges them → `{ "moved" }`
### `POST /api/videos/bulk` — `{ "action": "move", "ids": [...], "folder": "Q4" }`, `{ "action": "delete", "ids": [...] }` (to the trash), `{ "action": "restore", "ids": [...] }`, `{ "action": "purge", "ids": [...] }` (delete trashed videos for good; a video that is not in the trash is reported in `missing`), or `{ "action": "share", "ids": [...], "shareDisabled": true | false }` (switch the share links off or on) → `{ "done", "missing" }`
### `POST /api/videos/:id/share` — `{ "to": ["jane@example.com", ...], "message"?: string }`

Emails the share link of a **completed** video to up to 10 recipients (de-duplicated; `message` is an optional plain-text note of up to 500 characters shown above the link; a password-protected link tells the recipient a password is needed without including it). `404` for a video that is not yours, `409` while the render is not finished or the share link is off or expired, `429` beyond 60 recipients per sender per hour (600 per instance); a refused batch takes nothing from the allowance. The link uses `APP_URL` when it is set, otherwise the request's origin. ### `POST /api/video-agent` — a whole video from one prompt

```json
{ "prompt": "A TikTok explaining three tips for staging a home", "lengthSec": 60, "language": "English", "orientation": "auto", "mode": "generate" }
```

The script writer plans the video: a title, one scene per idea (a hook and a call to action framed as close-ups), and a frame orientation (portrait for social formats, landscape otherwise). `prompt` is 3–10,000 characters; `url` (optional) is a public web page the plan uses as its only source of facts, under the same rules as the script writer's; `document` (optional) is `{ "name", "text" }`, an attached document's words (1–12,000 characters; the page reads a PDF, Word, PowerPoint, or text file in the browser, telling the format by the file's first bytes, so only its name and words are sent), used the same way, and with a page as well both are passed to the planner, each named, the document first; `avatarId` and `voiceId` (optional) choose the presenter and voice, else the brand kit's defaults, else the first ones listed (a chosen presenter brings its own default voice); `orientation` is `auto`, `landscape`, `portrait`, or `square` (`auto` is 9:16 for a plan in a vertical format, 16:9 for a prompt that names a wide one — landscape, widescreen, horizontal, YouTube, or 16:9 — else the brand kit's default format, else 16:9); `lengthSec` is 15–300 (default 60); `mode` is `generate` (default) or `plan`. ## Interactive avatar

`POST /api/chat` returns one spoken-style reply in character. Keep the last 20 messages; the last one must be from the visitor. Rate limited to 60 turns per 10 minutes per client.

```json
{ "avatarId": "stock_1", "instructions": "You represent Acme Realty…", "language": "English",
  "messages": [{ "role": "user", "content": "Do you have open houses this weekend?" }] }
```

Returns `{ "reply": "…" }`.

## Translation

- `POST /api/translate` → `{ "title", "sourceVideoUrl", "targetLanguage" }` → `201 { "translation" }`, or `{ "title", "sourceVideoUrl", "targetLanguages": [...] }` (1 to 5 languages, repeats ignored without regard to case) → `201 { "translations" }`, one dubbing job per language, each titled `"<title> (<language>)"`. A HeyGen workspace has one glossary since October 2026, so every dub's rules go into that one: the studio's own (named `Avatar Studio`), else one made in HeyGen's app, else one of the studio's old per-set glossaries (`Avatar Studio terms <digest>`, from before the change; the first by id is renamed `Avatar Studio` and its `do_not_translate_terms` and `forced_translations`, which only the studio wrote and which applied in every language, cleared), else a new one (made with an `Idempotency-Key` of its own each time, so one deleted since is made anew), found through every page of the workspace's glossaries. Each rule is a `forced_translations` entry scoped to the dub's language (`target_language`, the language's base code: `Spanish (Mexico)` is `es`, so regional dubs of one language share their rules), a kept term as a translation to itself, since HeyGen's `do_not_translate_terms` apply in every language and win over a forced translation; a dub whose language has no code HeyGen's rules can name fails rather than writing a rule every language would follow. The glossary is read, the rules missing or different are added or replaced (the same term, matched without regard to case as HeyGen matches it, in the same language), everything else in it is kept as it is, it is written back, and it is read again to see the write held (a concurrent edit, HeyGen's `409`, or another writer putting its list back, is tried again, three times at most); one server instance writes one at a time, and a set of rules once written is trusted for ten minutes, until the instance writes another. A job the provider refuses is returned as failed while the rest start (the response then carries an `error` saying how many failed); `502` when none started

```js
export function verifyStudioWebhook(req, rawBody, secret, maxAgeSec = 300) {
  const ts = req.headers["x-studio-timestamp"];
  const sig = String(req.headers["x-studio-signature"] ?? "").replace(/^sha256=/, "");
  if (!ts || !sig || Math.abs(Date.now() / 1000 - Number(ts)) > maxAgeSec) return false;
  const expected = createHmac("sha256", secret).update(`${ts}.${rawBody}`).digest("hex");
  return expected.length === sig.length && timingSafeEqual(Buffer.from(expected), Buffer.from(sig));
}
```

Deliveries are attempted once, after the response that completed the render, with a 10-second timeout and no redirects. The last outcome is shown in Settings. Endpoints on private or local addresses are rejected, and the delivery connects only to the addresses that passed that check.

## HeyGen API version

HeyGen retires its v1 and v2 APIs on October 31, 2026, and rendering uses v3:
- the avatar list is `GET /v3/avatars/looks`, the account's own looks (`ownership=private`) in full and then HeyGen's preset library up to 20 pages, each look once. The voice list is `GET /v3/voices`, the voices cloned in the HeyGen account (`type=private`) and then the shared library, paged the same way;
- the avatar list leaves out any look that a custom portrait was made into, so the portrait is not listed twice;
- uploads are `POST /v3/assets` (multipart). Clips and background images keep their v3 asset id under `heygen:asset`, so one uploaded through v1 (its id under `heygen`) is uploaded again once;
- a custom portrait becomes a photo avatar (`POST /v3/avatars`, `type: "photo"`, kept under `heygen:look`). Its look is waited for for about ten seconds before the first render (`GET /v3/avatars/looks/:id`); several presenters in one video are waited for side by side. A render that finds the look still being prepared is stored as failed with "HeyGen is still preparing the photo avatar … Generate again in a minute" (`POST /api/videos` then answers `502` with that error, and a batch row fails). Later renders ask about the same look once, without waiting, so a batch's later rows fail fast instead of each waiting. A look HeyGen lost (`404`) or could not prepare is made again from the portrait, and other errors while asking (a key, a rate limit) are reported as they are. Portraits uploaded as v1 talking photos are made again once as v3 looks;
- a background colour is sent as `#rrggbb` (a `#rgb` is spelled out; any other colour fails the render with a message saying so);
- videos are `POST /v3/videos` with `type: "studio"`, and their status is `GET /v3/videos/:id`.

The v3 studio has no presenter layout or framing, on-screen text, background fit, or voice emotion. Those settings are kept with videos, copies, and templates, and the editor previews them, but they are not sent. A translation started on v2 is still asked about on v2 until v2 answers `404` or `410`. Interactive avatars use LiveAvatar, HeyGen's replacement for its v1 streaming API (see the live video routes above).

All HeyGen calls follow HeyGen's API reference. They are checked against stubbed requests only, not against the live API.

## Provider webhooks (inbound)

`POST /api/webhooks/:provider` (`heygen`, `did`) receives render callbacks. Set `WEBHOOK_SECRET` and configure the provider to call `https://<your-app>/api/webhooks/<provider>?secret=<WEBHOOK_SECRET>` (or send it as `x-webhook-secret`). Without the secret configured the route answers `503`; a wrong secret answers `403`.

## Example: render and wait

```bash
KEY=as_live_…
BASE=https://your-app.example.com
ID=$(curl -s "$BASE/api/videos" -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"title":"Hello","script":"Hi there.","avatarId":"stock_1","voiceId":"stock_voice_1"}' | jq -r .video.id)
until [ "$(curl -s "$BASE/api/videos/$ID" -H "Authorization: Bearer $KEY" | jq -r .video.status)" = completed ]; do sleep 5; done
curl -s "$BASE/api/videos/$ID" -H "Authorization: Bearer $KEY" | jq -r .video.videoUrl
```
